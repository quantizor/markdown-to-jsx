Raw HTML is now screened the way a browser reads it. If you render untrusted markdown, please upgrade. These inputs could reach a page with a live event handler or link, or stop rendering altogether:

- A dangerous tag right after a comment, processing instruction, or declaration, such as `<!--><svg onload=…>`, or hidden in a quoted attribute value, such as `<a title="--><img onerror=…>">` after an unfinished comment, no longer reaches the HTML or markdown output as written. Neither does a hidden tag with a quote left open, such as `<a e="--><b e=">">`, which could pair with a quote in a later block.
- `<script>`, `<iframe>`, and every other filtered tag are now filtered wherever they sit in raw HTML in the HTML output: after a comment, processing instruction, declaration, or CDATA section, such as `<!-- c --> <script>…</script>`, and inside one or inside an attribute value. An earlier block can leave a browser reading that text as live markup, as `<p><? a`, a blank line, then `<!-- x><script>…</script>` does. A comment stays invisible and an attribute keeps its value, so only the HTML source changes. The exception is CDATA inside SVG or MathML, which shows the `&lt;` as written.
- An SVG animation that targets a link or an event handler, such as `<a><set attributeName="href" to="javascript:…"/></a>`, loses its `attributeName`, which leaves it with nothing to change. Animating any other attribute works as before.
- A dangerous link in a `{…}` value, such as `<Btn action={javascript:…}>`, is removed like the quoted form. A `{…}` object or array stays as it is.
- An opening tag a browser reads but the library rejects, such as `<div onclick='…'--!>`, or one left unfinished at the end of an HTML block, is now emitted as text. This includes raw HTML inside `<pre>` in React.
- An entity in `<pre>` text, such as `<pre>a &lt; b</pre>`, shows as `a < b` in React, React Native, Solid, and Vue, as it does in a browser reading the HTML output. It showed as `&lt;`.
- A code fence's info string no longer carries a dangerous attribute onto the code element, such as ```` ```js onmouseover="…" ````.
- A link whose scheme is hidden behind a doubled entity, such as `[x](&amp;amp;#106;avascript:…)`, no longer reaches the HTML output as a live link. Every `&` in a link target is now written `&amp;`, which matches React, Solid, and Vue.
- `[x][^1]` no longer uses the footnote's text as a link target. With a definition for `[^1]`, it renders as `[x]` followed by the footnote reference.
- A footnote reference with no definition, such as `[^1]` or `[x][^1]`, stays as text, as GitHub shows it, rather than a superscript linking to nothing. `[^1](/u)` with no definition is a link. With `optimizeForStreaming`, a reference with text after it stays one, as its definition may still arrive, and one ending the text so far shows as `^1`, as any bracket there drops its brackets while a link may still open. A footnote name can't hold `[`, so `[^a[b]` is text even with a definition, which also keeps a long run of `[^` fast.
- The text inside a filtered tag such as `<iframe>` is screened, and an unfinished tag in that text no longer goes live through a closing tag the output added.
- `<div innerHTML="…">` no longer puts markup into the page in Solid or Vue, and Solid's `attr:`, `prop:`, and `bool:` prefixes no longer carry a handler or a dangerous link past the screen. React's `xlinkHref` is checked like `xlink:href`.
- `ref`, `dangerouslySetInnerHTML`, and `children` in markdown no longer crash rendering. `ref`, `dangerouslySetInnerHTML`, `innerHTML`, and `outerHTML` are removed on every tag, and `children` is removed unless `overrides` lists the tag, or `evalUnserializableExpressions` is on for a capitalized or hyphenated tag, and its value is not an object or array.
- A `children` attribute or inner text on a tag that `overrides` keeps or renames to a void element, such as `<Foo children="x"/>` with `Foo` renamed to `img`, no longer crashes rendering in React or React Native.
- A `{…}` event handler on a hyphenated tag, such as `<my-widget onclick={…}>`, is removed unless `overrides` lists the tag or `evalUnserializableExpressions` is on.
- A `{…}` event handler on a capitalized tag, such as `<Img src=x onerror={steal()}>`, is removed from the HTML and markdown output and from native elements in Solid and Vue unless `overrides` lists the tag or `evalUnserializableExpressions` is on. A browser ran it as soon as the page loaded, and in Solid it stopped rendering altogether. React, React Native, and `parser()` keep it as a prop, so a component you supply through `createElement` or `renderRule` still receives it.
- An event handler name with no value, such as `<Img src=x onerror>` or `<my-widget onclick>`, no longer stops rendering in Solid or throws on click there.
- `<pre><b>x</b></pre>` renders its markup in Solid and Vue rather than `[object Object]`.
- `<pre>a` and `<div </div>'` no longer overflow the stack in Solid and Vue.
- `<?php … ?>`, `<!DOCTYPE html>`, and `<![CDATA[…]]>` no longer crash rendering in React. React, React Native, Solid, and Vue render nothing for them, as a browser does.
- A tag named after a built-in object property, such as `<Constructor>`, no longer crashes rendering when `overrides` is set.
- `sanitizer` now rejects a URL whose scheme is split by a tab or line break, such as `java\tscript:alert(1)`.

The markdown output is held to the same bar, because another renderer reads it:

- Raw HTML in a footnote definition is screened, and unsafe link targets are removed, including in raw HTML, autolinks, footnotes, and reference definitions.
- A link that hides inside autolink-shaped text, such as `<span>[x <https:a](javascript:…)></span>`, no longer reaches another renderer as a live link. Neither does one whose autolink is blocked by a second `<`.
- A code block or code span whose contents or fence language would be unsafe read as raw HTML or a link, such as `` `<img onerror=…>` ``, is written as HTML with entities, such as `<code>&lt;img onerror=…></code>`. Another renderer can read the markup around code differently from this library, for example after `<pre/>`, an odd CDATA end, or a tag renamed in `overrides`, and take the code's contents as raw HTML. A browser shows the same characters, and all other code keeps its backticks or fence.
- A link or reference definition split across raw HTML and the next line of a list item, such as `- <?a ?><?b ?>[x](` then `javascript:…)`, or `- <?a ?>[x]:` then `javascript:…`, no longer reaches another renderer as a live link.
- A tag renamed in `overrides`, such as `pre` to `div`, can no longer split raw HTML so that text in it reads as a live attribute. What a rename writes is read again like any other markdown, so it can differ slightly from before: `<span>y</span><b>z</b>` with `span` renamed to `div` is written with a blank line after `</div>`, the same as `<div>y</div><b>z</b>` with no rename.
- A code block in an ordered list no longer gains a space on every line each time it passes through the markdown output. Continuation lines now indent to the width of the list marker.
- A heading ending in a `#` after a space, such as `a #` underlined with `=`, keeps that `#`: it is written `# a \#`. It used to be read as the heading's closing mark and lost.
- A `<` before a letter in text, such as `&lt;img onerror=…&gt;` or `\<img onerror=…>`, is written `&lt;` so another renderer shows it as text. A quote in image alt text is written `&quot;`, as some renderers copy alt text into the page unescaped, and a bracket there is escaped so the image can't end early. With `disableParsingRawHTML`, raw HTML is written as text in the same way.
- A code block after raw HTML in a list item is written with a blank line before it, so another renderer can't read its contents as HTML.
- A link target with a numeric entity a browser decodes but markdown does not, such as `&#106avascript:` with no semicolon or `&#00000000106;avascript:` with extra zeros, is removed.
- A start tag inside a processing instruction or CDATA section, past its first `>`, such as `<?a><b c="?>">`, is written as text. Some renderers end that markup inside the tag's value, which let the tag's quote pair with one in a later block and read text there as attributes.
- `[^1]:` in a paragraph, heading, or list item is written `[^1]\:` when `[^1]` has a definition, and `\[^1\]:` when it has none, so a renderer without footnotes can't read it as a link definition. It renders the same.
- A byte order mark at the start of a block of text is written as `&#xFEFF;`. Some renderers drop one at the start of a document and others keep it, so the text after it could be a link definition to only one of them.
- A comment, processing instruction, or similar opener with no end, on its own line past the first line of raw HTML, such as `<title>a` then a blank line then `<!--</title>`, is written as text. A renderer would treat the rest of the document as raw HTML, and a browser would read its text as written.
- A U+2028 or U+2029 line separator right before a `>` in raw HTML is written as an entity, or its tag as text, as some renderers strip that `>` in a blockquote, which changes where the tag ends.
- A footnote or reference name holding markup, such as `[^a<img onerror=…>]`, and a link in a link's or reference definition's title no longer read as live for a renderer that treats those lines as text. Those characters are written as entities.
- `[^a](javascript:…)` with a definition for `[^a]`, and escaped text in link text such as `[\[a\](javascript:…)](/u)`, no longer read as a live link in the markdown output: the `(` is written `\(`. It renders the same.
- Text that reads like an entity after decoding, such as `&amp;copy;`, stays `&amp;copy;` in the markdown output. It was written as `&copy;`, which turned it into a `©`.
- A heading written across several lines with a `=` or `-` underline now keeps all its lines in the heading. Every line but the first used to fall out of it.
- A table cell keeps its backslashes and escaped pipes when written back, and an empty `~~~~` strikethrough is written `\~\~\~\~`, so it can't open a code block or join the text around it into a link.
- A link or image whose URL mentions a dangerous scheme after its first `/`, `?`, or `#`, such as `https://en.wikipedia.org/wiki/Javascript:_The_Good_Parts` or `https://example.com/?q=javascript:x`, keeps its URL, as a browser can't read a scheme there. `sanitizer` returns these URLs too, where it returned `null`. The markdown output still removes one holding a character another renderer can split at, such as a bracket.
- Raw HTML in a list item that continues on a line with no indent, such as `- <pre>x` then `y</pre>`, no longer carries a stray control character (U+001E) into the output, and an event handler on such a line, such as `- <div` then `onclick=alert(1)>`, is removed. A line with no indent after a closed HTML block in a list item now reads as CommonMark's block rules say rather than as paragraph text, so `[^1]: x` there is a definition. A code block, table row, reference definition, or footnote in a list item that continues on such a line no longer carries that character either, which used to break a link such as `1. [r]:` then `/u`.
- In a list item, a raw opening tag written across lines, such as `- <b>f</b><!-- c --><img` then `src=x>z onclick=…`, is written on one line, with `&#10;` for a line break inside a quoted value and a space for one inside a `{…}` value, which changes a multi-line string there. Another renderer could end its HTML block where the tag started and read the text after the tag as that tag's attributes.
- A reference definition's destination ends at whitespace even after a backslash, as CommonMark says: `[r]: a\` then `b` keeps `b` as text rather than taking it into the URL. The markdown output writes a backslash in a link target as `\\` where it would read as an escape, so `[x](a\\)` stays a link in every renderer.
- A link target with a space or an angle bracket, such as `[x](<a b>)`, is written percent-encoded, `[x](a%20b)`, and one with a parenthesis that has no partner keeps its angle brackets, such as `[x](<a)b>)`. It used to lose them, which turned the link into text or read part of its target as a second link.

CommonMark examples 156 to 158 now render their unfinished tag as text on purpose. In the HTML and markdown output, a long quoted value holding something that reads as an unfinished tag loses that attribute or is shown as text, which stays fast on hostile input. A long run of HTML blocks inside a component's body also no longer slows down with the square of its length. Deeply nested HTML blocks, long runs of unclosed HTML tags, repeated `<pre></pre>` blocks, and long runs of unclosed `<!--`, `<?`, `<!`, or `<![CDATA[` no longer slow rendering sharply: nested `<div>`s in a 30 KB document took about 40 seconds.
